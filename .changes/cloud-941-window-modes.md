# omuzaki-stream: window modes (studio, capture, desktop) for the output window

- `omuzaki-stream-api::window`: `WindowMode` (`studio`: only in the studio; `capture`: the clean window a capture tool grabs; `desktop`: the character alone on the desktop, transparent, on top, out of the taskbar), `ClickThrough` (`off`, `transparent`, `full`), `DesktopSettings` (opacity and click-through) and `ModeSupport` (whether this machine can show a mode, and a reason a person can read when not). `WindowSettings` gains `mode` and `desktop`, and `WindowState::Open` reports them. `WindowHost` gains `modes()` and `set_desktop()`, both with defaults, so existing hosts compile unchanged and report the desktop mode as unavailable until they build it.
- `output.window.open` takes `mode`, `opacity` and `click_through`. `studio` closes the window. `desktop` is always transparent, on top, with the pointer shown, at half the output unless a scale is asked for. A mode the host can't show is refused with the host's reason. `output.window.status` lists the modes with their reasons. The new `output.window.set { opacity?, click_through? }` changes an open desktop window live.
- Every click passing through (`click_through: full`) needs a person: an agent's request waits for one, since the person could lose the character on the desktop. An agent's `output.window.open` now opens the window without saving it as the person's `output.window` choice (it used to wait for a person).
