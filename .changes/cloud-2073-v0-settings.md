# omuzaki-stage, omuzaki-track: the V0 settings survive a restart (#2073, #418)

- `perform::settings` registers the V0 keys beside `input.source` and `input.camera`: `perform.retarget` (smoothing, exaggeration, head gain, mirror; User, free for agents, profile member), `perform.triggers` (the expression hotkeys, at most 16, keys distinct; User, free, member) and `perform.calibrations` (Machine, an agent's write is confirmed, not in profiles). `restore` puts them back at start, with the calibration saved for the character and device class, and reports what did not come back (findings naming their keys, a camera that is not connected, a hotkey the performer refused); `save` and `save_calibration` write the live state.
- `omuzaki-track::calibration::CalibrationStore` keeps finished calibrations by character and device class, writes no `null` (TOML has none), checks every range before it is used and never hands back another character's or another device's.
- An unusable stored value never fails the start: the key reads as its default and a finding names it.
- `restore` also reads the output window's own key, `output.window` (written by `output.window.open`), and returns it as `Restored::output_window` for the app to open the window with; a bad stored value is a finding naming the key and `None`.
