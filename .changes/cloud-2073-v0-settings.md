# omuzaki-stage, omuzaki-track: the V0 settings survive a restart (#2073, #418)

- `perform::settings` registers the V0 keys beside `input.source` and `input.camera`: `perform.retarget` (smoothing, exaggeration, head gain, mirror; User, free for agents, profile member) and `perform.triggers` (the expression hotkeys, at most 16, keys distinct; User, free, member). `restore` puts them back at start, with the calibration saved for the character and device class, and reports what did not come back (findings naming their keys, files that did not parse, a camera that is not connected, a hotkey the performer refused); `save` and `save_calibration` write the live state.
- The calibrations are state, not a setting (ADR 0026, #315): `omuzaki-track::calibration::CalibrationStore` keeps them in their own file, `perform/calibration.toml` in the local data folder (`calibration_file`). Every `[[calibration]]` element is read on its own; one that cannot be used is kept exactly as it was, listed in `Restored::calibration_findings` and never rewritten, so it costs the person none of the others. A file that cannot be read at all (it does not parse, an unknown version) locks the store: nothing is written over it. Written atomically, with no `null`, every range checked before use, never another character's or device's calibration.
- An unusable stored value never fails the start: the key reads as its default and a finding names it. A settings file that does not parse is a finding with no key and its file name, so the person is told why nothing came back.
- `restore` also reads the output window's own key, `output.window` (written by `output.window.open`), and returns it as `Restored::output_window` for the app to open the window with; a bad stored value is a finding naming the key and `None`.
- `PerformHost::bind_triggers` binds a whole set in one queue slot (`restore` makes three requests, not 18), and `PerformHost::requested_retarget` and `requested_calibration` give the state once every request has run, so `save` and `save_calibration` store what an op asked for before the performer has applied it.
