# omuzaki-ui: the Live UI (V0): the Live workspace, the clean output window and the live wiring

- `live::wiring`: the perform loop on its own thread (`omuzaki-perform`) at the performer's fixed 60 Hz step, a lock-free newest-wins mailbox to the render side, `LiveScene` (the newest frame through `Stage::tick` into the renderer's `Scene`), and `LiveRig`, which owns the tracker and the perform thread and stops them in the documented quit order. The app starts it at launch (`LiveApp`): the op runner holds the performer in its services, so `perform.*` and `trigger.*` reach the running loop, the triggers start on the starter expressions, and the performer runs on the life layer until the webcam tracker is linked in. A headless test runs `FakeCamera`'s tracker to scenes at 60 Hz for 10 s with no allocation on the perform thread after warm-up (#312).
- `output_window` and `aux_window`: a borderless window exactly the output size in physical pixels at any scale, showing the program frame over the key colour, or over nothing where a transparent surface is verified (and saying `fallback` elsewhere); placement remembered per monitor arrangement. `OutputHost` is the app's `WindowHost` (`omuzaki-stream-api`): the `output.window.*` ops queue an open or a close, the UI thread carries it out on its next frame and publishes the window's size, backdrop and minimised state for `output.window.status` (#299).
- `live`: the Live workspace (health, output, character, camera, calibrate, smoothing, hotkeys), every action an op: `perform.*`; the hotkey table binds the key pressed on a row's trigger button with `trigger.bind`, unbinds with `trigger.unbind` and shows what `trigger.list` lists; the output switch, backdrop and Keep on top run `output.window.open` and `close` and show `output.window.status`; the camera picker and Track my face run the `input.*` ops (`input.bind_camera`, `input.select`, `input.preview`, `input.request_camera`, read through `input.state`), which stay disabled and say "not available yet" until the stage registers them; its gallery story and the `live-workspace` evidence case (#305).
- `live::registration`: the Live panel (`live`, right dock), the Perform workspace (`perform`, Run group: the viewport and the Live panel) and the Live story, registered with `omuzaki-ui-api`; the panel passes `omuzaki-ui-mock`'s conformance check.
