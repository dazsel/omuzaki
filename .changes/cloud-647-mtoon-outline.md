# MToon outlines as the file draws them

- `Material.outline_style: OutlineStyle { width_mode, width_texture, lighting_mix }` (#647). `OutlineStyle::KIT` is the kit's line as before (`OutlineWidthMode::WorldByDistance`). `World` is a constant width in metres; `Screen` is a constant fraction of the target's height, pushed in clip space along the projected normal, so a line stays the same number of pixels at any distance. The width texture's green channel scales the width per vertex, and `lighting_mix` moves the line's light from the scene's outline light toward the lit surface's colour (three-vrm's `outlineLightingMixFactor`).
- `omuzaki-render` and the mock draw all three, and report `MtoonSupport::OUTLINE_STYLE`. The material bind group gains bindings 11 and 12 (the width texture and its sampler, vertex stage).
- An imported VRM keeps each material's MToon outline in `ImportedAvatar::outlines` (`AvatarOutline`), and the stage applies it, so `look.mtoon_not_drawn` no longer lists the screen width, the outline lighting mix or the width texture on these renderers.
- Measured on lavapipe and the mock (`crates/omuzaki-render/tests/outlines.rs`): a 4% screen line is 5 px at a 128 px height (5.12 wanted) at 1, 3 and 9 m, whatever the sphere's size; a 3 cm world line matches its projected width at 1, 2, 4 and 8 m; a white line around a dimly lit white sphere reads 1.000, 0.567 and 0.132 at mixes 0, 0.5 and 1.
